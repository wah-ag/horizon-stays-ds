# Tokens — export and rebuild

## When to use this
When tokens are re-exported from Figma, when a build or component needs a token that seems not to
exist, or when you need to know which mode a value comes from. The Figma sync itself — branch,
build, summarise, PR — is run by `token-runner`; this skill is the knowledge it and every other
agent rely on.

## The rule
**A missing token is reported and fixed in Figma. It is never added to a generated file.**

Not to `config/`, not to `tokens/`, not injected by `config.js`, and not declared as a local
custom property inside a component. A token added anywhere but Figma is silently destroyed by the
next export, or silently survives it and drifts from the design. Either way nobody designed it.
Report the gap, name what needs it, and stop.

## What is generated — never hand-edit
| Path | Written by | Committed | Rule |
|---|---|---|---|
| `tokens/` | The Figma **Design Tokens** plugin (DTCG: `$type`, `$value`, `$description`) | Yes — this is what ships | Never edit. Wrong value → fix in Figma, re-export. |
| `config/` | `npm run build:tokens` (`node config.js`) from `tokens/` | No — gitignored | Never edit, never commit. Rebuild. |
| `storybook-static/` | `npm run build-storybook` | No — gitignored | Never edit. Rebuild. |

`config.js` is the build, not a token source. Changing it is a tooling change: read `tools.md`
first. Every file it writes starts with "generated by config.js — Do not edit directly."

## Exporting
1. In Figma, export with the Design Tokens plugin in DTCG format — every collection and every mode.
2. The export replaces the files in `tokens/` whole. Never merge an export into the old files by
   hand, and never keep an old file the new export did not write.
3. `tokens/manifest.json` lists every collection, mode and style file. A collection or mode
   missing from it is a broken export, not a smaller design.
4. Hand the change to `token-runner`: it branches, builds, summarises the diff in designer
   language, and opens a PR with `tokens/` staged alone.

## Modes — what varies and what does not
Three collections, two style groups. Mode is a file, never a name suffix: the same token name
resolves differently per mode, and there is no `-dark` or `-mobile` in any name.

| Source | Modes | Varies by | Built to (CSS) | How a mode is chosen |
|---|---|---|---|---|
| `core` | `value` (one) | Nothing | `core.css` | — |
| `semantics-color` | `on-light`, `on-dark` | **Theme** | `semantic-light.css`, `semantic-dark.css` | `[data-theme="dark"]` on an ancestor; `prefers-color-scheme` when no `data-theme` is set. Android `values-night/`. |
| `type-scale` | `web`, `mobile`, `back-office` | **Platform** | `type-scale-web.css`, `-mobile`, `-back-office` | The entry point: `index.css`, `index-mobile.css`, `index-back-office.css` |
| `typography` styles | None of its own | **Platform** — each role resolves against the type scale | `typography-web.css`, `-mobile`, `-back-office` | The entry point |
| `effects` styles | None | Nothing | `elevation.css` | — |

So: **colour varies by theme and never by platform; size and type vary by platform and never by
theme; core primitives and elevation do not vary.** A colour that differs between web and mobile,
or a font size that differs between light and dark, is wrong.

Every mode of a collection must hold exactly the same token names. A name present in one mode and
missing from another is a **design gap** — report it; never fill the missing mode so a table looks
complete.

Get the current counts from the build, not from memory:

```bash
node -e '
const fs = require("fs");
const names = (f) => new Set([...fs.readFileSync(`config/css/${f}`, "utf8").matchAll(/^\s*(--[a-z0-9-]+):/gm)].map((m) => m[1]));
for (const group of [["semantic-light.css", "semantic-dark.css"],
                     ["type-scale-web.css", "type-scale-mobile.css", "type-scale-back-office.css"],
                     ["typography-web.css", "typography-mobile.css", "typography-back-office.css"]]) {
  const sets = group.map(names);
  const all = new Set(sets.flatMap((s) => [...s]));
  group.forEach((f, i) => {
    const missing = [...all].filter((n) => !sets[i].has(n));
    console.log(`${f}: ${sets[i].size} tokens${missing.length ? `, MISSING ${missing.join(" ")}` : ""}`);
  });
}'
```

## A real gap, or a naming mistake?
Before reporting a token as missing, prove it is missing. Work down this list and stop at the
first match:

1. **Search the build, every mode.** `grep -rn -- "--<name>" config/css/`. Then search by the role
   word alone (`brand`, `disabled`, `hovered`) to find near names.
2. **It exists under another name → naming mistake in your code.** Typical causes: words out of
   order (names read category → property → role → variant: `color-text-disabled-primary`), a
   variant spelled differently (`hover` for `hovered`), a mode suffix (`-dark`), or a core
   primitive (`--color-blue-500`) where a semantic role (`--color-text-brand`) exists. Use the
   existing name. Nothing to report.
3. **It exists, but its Figma name breaks the naming convention** → report a naming issue to
   design. Never rename in the pipeline; token names come from Figma.
4. **It exists in some modes and not others** → a design gap in the missing mode. Report it.
5. **It is a Figma variable but not in `tokens/`** (check with `get_variable_defs` on the node) →
   an export problem. Re-export every collection and mode; do not patch the file.
6. **The Figma node uses a raw value, bound to no variable** → a design gap: the design left the
   property unbound. Report it.
7. **An `a`-suffixed token exports opaque** → misnamed: `a` means it carries alpha. Report it.
8. **No token with that meaning exists in any mode, and Figma has no variable for it** → a real
   token gap. Report the property, the node, and the role it needs. Stop.

Only step 2 is yours to fix. Every other outcome is a report, and the fix happens in Figma.

## Verify the rebuild — don't assume it
A green build is not proof that an export is sound. It proves the references resolved, nothing
more. After every export:

1. **Before exporting, keep the old output.** `config/` is gitignored, so git cannot show you what
   changed: copy it aside (`cp -r config ../config-before`).
2. **Build.** `npm run build:tokens` must exit `0`. Read the whole output: anything under
   "⚠ Source-data warnings" is a Figma problem, and every one is reported — a warning is not a pass.
3. **Mode parity.** Run the count command above. Every mode of a collection has the same names.
4. **Diff the names.** Compare `config/css/` against the copy. For every **removed or renamed**
   token, search `src/` and `stories/` for `var(--<name>)`: a component still using it will
   silently lose its value.
5. **Diff the values.** Every changed value is summarised in designer language — "brand blue 600
   got darker, `#3676E0` → `#3260AC`", not "line 47 changed". A change nobody asked for is a finding.
6. **Alpha.** Every `a`-suffixed token resolves to a colour with alpha below 1.
7. **Render.** `npm run build-storybook` completes, and the foundation stories — colour, dimensions,
   type scale, typography, elevation — render from the new build. They read `config/css/*.css`
   through `stories/lib/tokens.js`, so a missing or renamed token shows up there.
8. **Components.** Open every component story in both themes. A token that changed under a
   component changes that component.

**Check:** every step above ran, and every warning, gap, removal and unrequested change is reported.

## Known exceptions in the build today
These already break the rule above. They are reported here so nobody copies them; each should be
fixed in Figma, and the workaround removed from `config.js`.

- **Injected shadow tints.** `effects.styles.tokens.json` references `elevation-color-6a`, `-8a`,
  `-10a` and `-12a`, which the export does not contain. `config.js` injects them as grey/800
  (`#31373D`) at 6, 8, 10 and 12% alpha. Fix: add the four variables to the `core` collection in
  Figma.
- **Silent fallbacks.** `config.js` defaults an unknown font weight to `400` (with a warning), a
  missing font family to `Inter` and a missing font size to `16px` (without a warning), and emits
  a `0` line height as `normal` (with a warning). Each fallback hides a value the design did not
  provide. (Translating a weight name such as `Regular` to `400` is a translation, not a fallback.)
- **`a`-suffixed tokens that export opaque.** `--color-blue-100a` (`#e4eefe`),
  `--color-blue-500a` (`#5f98f5`), `--color-grey-100a` (`#eff1f2`) and `--color-grey-800a`
  (`#31373d`) carry the alpha suffix but no alpha. Either the alpha is missing in Figma or the
  names are wrong — a design question. Fix in Figma.
